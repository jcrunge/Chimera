# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

**Chimera** is a multi-agent AI system running entirely on local hardware (Mac Mini M4 with Apple Silicon). It uses MLX-accelerated LLMs, a shared ChromaDB vector memory, and a Docker sandbox for safe code execution. The system is designed for minimal latency on-device inference.

## Running the System

**Prerequisites:** Docker Desktop must be running before starting anything that executes code.

```bash
# Activate the virtual environment first (always required)
source .venv/bin/activate

# Primary entry point — interactive mode
python harness.py --interactivo

# One-shot task
python harness.py "Investiga sobre X"

# REST API server (port 5555)
python chimera_api.py

# Voice interface (requires microphone + API server running)
python chimera_voz.py

# (Re)build the swappable-chip index in ChromaDB — run after editing any chip or _metadata.json
python indexador_chips.py

# Ingest PDFs from Biblioteca/ into ChromaDB
python asimilador_libros.py

# Ingest a web URL into ChromaDB
python asimilador_web.py

# Inspect / delete entries in ChromaDB
python gestor_memoria.py
```

## Architecture

The system is organized in layers, each represented by a module:

### Core Flow (`harness.py` → `ChimeraHarness`)
`harness.py` is the main orchestrator. It loads two MLX models at startup — a larger *orquestador* (Qwen 7B) for planning/reasoning and a smaller *worker* (Llama 3B) for code/evaluation — and wires them to specialized `Neurona` agents.

Every task enters `ChimeraHarness.procesar()`, which calls the **Planner** to decompose the task into a JSON list of typed steps (`INVESTIGACION`, `CODIGO`, `AUDITORIA`; the planner prompt itself only emits the first two, but the harness has a flow handler for each). Steps are executed sequentially with accumulated context passed forward. Before each step runs, `_seleccionar_chips()` queries the chip index for swappable chips relevant to that sub-task and layers them on top of the agent's base chip (see Chips Cognitivos below).

### Agents (`neuronas.py` → `Neurona`, `REGISTRY`)
Each `Neurona` holds a fixed system prompt (role + instructions). `crear_neurona(tipo)` looks up the type in `REGISTRY` and dynamically appends any matching **Chip Cognitivo** file from `Chips_Cognitivos/chip_<tipo>.txt` to the system prompt. Model assignment is done via `set_modelo()` after creation.

Active agents: `planner`, `investigador`, `sintetizador`, `coder`, `tester`, `citation`.

### Memory (`herramientas.py`, `BaseDatos_Vectorial/`)
ChromaDB persists two collections in `BaseDatos_Vectorial/`:
- **`memoria_neuronal`** — shared agent memory. `buscar_memoria()` / `guardar_en_memoria()` are the only interface. Also holds the chunked content of `rag`-mode chips (tagged `origen=<chip>`).
- **`indice_chips`** — the swappable-chip index built by `indexador_chips.py`. Queried via `buscar_chips_relevantes()` (returns `{nombre, similaridad, metadata}`, similarity ∈ [0,1]) and `cargar_chip_completo()`.

### Docker Sandbox (`docker_sandbox.py` → `DockerSandbox`)
Spins up a persistent `python:3.11-slim` container named `chimera_sandbox` with `./workspace` mounted at `/workspace`. `ejecutar_codigo()` writes code to `workspace/script.py` and runs it inside the container. Always call `apagar()` when done.

### Chips Cognitivos (`Chips_Cognitivos/`)
Plain `.txt` files that extend a `Neurona`'s system prompt at runtime. There are **two layers**:

1. **Base chip** — `crear_neurona(tipo)` auto-appends `chip_<tipo>.txt` to the agent's instructions (the investigador also gets `chip_biblioteca.txt`, which is auto-generated by `asimilador_libros.py`). To permanently specialize an agent, edit `chip_<agent_type>.txt`.
2. **Swappable chips (Matrix-style "load skills on demand")** — domain chips (`chip_red_team`, `chip_experto_python`, `chip_filosofia`, …) that any agent can have layered on top per-step. `_seleccionar_chips()` picks them by semantic similarity against the `indice_chips` collection, then `crear_neurona(tipo, chips_extra=[...])` injects their content.

`_metadata.json` declares each chip's `descripcion`, `keywords`, `requiere_autorizacion`, and `modo`:
- **`modo: inline`** — full text is injected directly.
- **`modo: rag`** — only the description is indexed; the body is chunked into `memoria_neuronal` and pulled back by similarity at load time (used for large book-chips like `chip_teoria_musical`, `chip_linux_master`).
- **`requiere_autorizacion: true`** — gated behind a higher similarity threshold (`umbral_chip_autorizado`), so e.g. `chip_red_team` only loads when the task semantically calls for it.

**Any edit to a chip's content or `_metadata.json` requires re-running `python indexador_chips.py`** — the index is a snapshot, not read live.

### API & Integrations
- `chimera_api.py` — FastAPI server (port 5555). Endpoints: `/pensar`, `/chat`, `/investigar`, `/siri`.
- `chimera_voz.py` — Records microphone audio, transcribes with MLX Whisper, posts to `/chat`.
- `puente_siri.py` — Thin CLI client for Apple Shortcuts to call `/siri`.

## Configuration (`config_chimera.json`)

```json
{
  "modelo_orquestador": "mlx-community/Qwen2.5-7B-Instruct-4bit",
  "modelo_worker": "mlx-community/Llama-3.2-3B-Instruct-4bit",
  "max_tokens_pensamiento": 1500,
  "max_tokens_codigo": 2000,
  "max_intentos_correccion": 3,
  "max_iteraciones_investigacion": 5,
  "temperatura": 0.1,
  "umbral_chip_normal": 0.35,
  "umbral_chip_autorizado": 0.40,
  "max_chips_por_paso": 2
}
```

Change models here without touching code. The harness reads this at startup with sane defaults (note: `cargar_config()`'s in-code defaults for the chip thresholds differ from the JSON — the JSON file wins when present). The last three fields tune swappable-chip selection: minimum similarity to load a normal chip, the higher bar for `requiere_autorizacion` chips, and the per-step cap.

## Key Invariants

- `OBJC_DISABLE_INITIALIZE_FORK_SAFETY=YES` must be set before importing MLX on macOS (already done in `harness.py`).
- `multiprocessing.set_start_method("spawn", force=True)` is required for MLX + multiprocessing.
- The `Neurona.pensar()` method strips markdown code fences from LLM output automatically — callers receive raw text or raw code, not fenced blocks.
- **Structured evaluator protocol (do not break this):** every evaluator agent (`tester`, `citation`, and the `investigador` in completeness-judge mode) must end its output with `<resultado>EXITO|FALLO|INCOMPLETO</resultado>`. The harness parses this with `_extraer_resultado()` (regex in `harness.py`), **not** substring matching. When editing any evaluator prompt or its chip, keep that exact token format or the control flow silently treats the step as failed. (This replaced the old `COMPLETO` / `EXITO_TOTAL` substring conventions — those strings are gone.)
- A research step succeeds only when the investigador judges the synthesis `EXITO` **and** the CitationAgent returns `EXITO`; otherwise it loops up to `max_iteraciones_investigacion`, appending a `[PENALIZACIÓN]` note to drive the next attempt.
