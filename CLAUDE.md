This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

**Jarvis** is a multi-agent AI system running entirely on local hardware (Mac Mini M4 with Apple Silicon). It uses MLX-accelerated LLMs, a shared ChromaDB vector memory, and a Docker sandbox for safe code execution. The system is designed for minimal latency on-device inference.

## Running the System

**Prerequisites:** Docker Desktop must be running before starting anything that executes code.

```bash
# Activate the virtual environment first (always required)
source .venv/bin/activate

# Primary entry point — interactive mode
python harness.py --interactivo

# One-shot task
python harness.py "Investiga sobre X"

# REST API server (port 5555)
python jarvis_api.py

# Voice interface (requires microphone + API server running)
python jarvis_voz.py

# Ingest PDFs from Biblioteca/ into ChromaDB
python asimilador_libros.py

# Ingest a web URL into ChromaDB
python asimilador_web.py

# Inspect / delete entries in ChromaDB
python gestor_memoria.py
```

## Architecture

The system is organized in layers, each represented by a module:

### Core Flow (`harness.py` → `JarvisHarness`)
`harness.py` is the main orchestrator. It loads two MLX models at startup — a larger *orquestador* (Qwen 7B) for planning/reasoning and a smaller *worker* (Llama 3B) for code/evaluation — and wires them to specialized `Neurona` agents.

Every task enters `JarvisHarness.procesar()`, which calls the **Planner** to decompose the task into a JSON list of typed steps (`INVESTIGACION`, `CODIGO`, `AUDITORIA`). Steps are executed sequentially with accumulated context passed forward.

### Agents (`neuronas.py` → `Neurona`, `REGISTRY`)
Each `Neurona` holds a fixed system prompt (role + instructions). `crear_neurona(tipo)` looks up the type in `REGISTRY` and dynamically appends any matching **Chip Cognitivo** file from `Chips_Cognitivos/chip_<tipo>.txt` to the system prompt. Model assignment is done via `set_modelo()` after creation.

Active agents: `planner`, `investigador`, `sintetizador`, `coder`, `tester`, `citation`.

### Memory (`herramientas.py`, `BaseDatos_Vectorial/`)
All agents share a single ChromaDB collection named `memoria_neuronal` stored persistently in `BaseDatos_Vectorial/`. Functions `buscar_memoria()` and `guardar_en_memoria()` are the only interface to it.

### Docker Sandbox (`docker_sandbox.py` → `DockerSandbox`)
Spins up a persistent `python:3.11-slim` container named `jarvis_sandbox` with `./workspace` mounted at `/workspace`. `ejecutar_codigo()` writes code to `workspace/script.py` and runs it inside the container. Always call `apagar()` when done.

### Chips Cognitivos (`Chips_Cognitivos/`)
Plain `.txt` files that extend a `Neurona`'s system prompt at runtime. To specialize an agent, create or edit `chip_<agent_type>.txt`. The `chip_biblioteca.txt` file is auto-generated by `asimilador_libros.py` after ingesting PDFs.

### API & Integrations
- `jarvis_api.py` — FastAPI server (port 5555). Endpoints: `/pensar`, `/chat`, `/investigar`, `/siri`.
- `jarvis_voz.py` — Records microphone audio, transcribes with MLX Whisper, posts to `/chat`.
- `puente_siri.py` — Thin CLI client for Apple Shortcuts to call `/siri`.

## Configuration (`config_jarvis.json`)

```json
{
  "modelo_orquestador": "mlx-community/Qwen2.5-7B-Instruct-4bit",
  "modelo_worker": "mlx-community/Llama-3.2-3B-Instruct-4bit",
  "max_tokens_pensamiento": 1500,
  "max_tokens_codigo": 2000,
  "max_intentos_correccion": 3,
  "max_iteraciones_investigacion": 5,
  "temperatura": 0.1
}
```

Change models here without touching code. The harness reads this at startup with sane defaults.

## Key Invariants

- `OBJC_DISABLE_INITIALIZE_FORK_SAFETY=YES` must be set before importing MLX on macOS (already done in `harness.py`).
- `multiprocessing.set_start_method("spawn", force=True)` is required for MLX + multiprocessing.
- The `Neurona.pensar()` method strips markdown code fences from LLM output automatically — callers receive raw text or raw code, not fenced blocks.
- The investigation loop's termination condition requires the LLM to explicitly output `COMPLETO` (uppercase) AND the CitationAgent must not output `[VERIFICACION_FALLIDA]` or `[FALTA_FUENTE]`.
- Code execution feedback uses `EXITO_TOTAL` (tester) while the harness checks for `EXITO` substring — keep both consistent when modifying evaluation prompts.
